# Feasibility of the 4G LTE downlink as an illuminator of opportunity for passive bistatic radar

MATLAB simulation study for the Skill Development Course *4G LTE Communication
Systems* (24SDEC05A).

The question is whether an ordinary LTE base station, transmitting for its own
purposes, can be used as the transmitter of a radar that has no transmitter of
its own. The project answers it in three parts:

1. **Does the LTE waveform have a usable ambiguity function, and where are its
   false peaks?** Yes, when the cell is carrying traffic. No, when it is idle:
   the reference signals alone put a ghost at 3.33 km that is 2.6 dB below the
   true peak.
2. **How does detection depend on the traffic the cell is carrying?** Strongly.
   Peak sidelobe level goes from -2 dB on an idle cell to -21 dB on a fully
   loaded one.
3. **What is the maximum detection range?** About 30 km for a car and 10 km for
   a pedestrian, in free space, with 0.2 s of coherent integration. And it does
   not depend on the channel bandwidth, for a reason worth reading about below.

Base MATLAB only, R2023b or later. No toolbox is used anywhere: no LTE Toolbox,
no Signal Processing Toolbox, no Phased Array System Toolbox. `xcorr`,
`ambgfun`, `lteOFDMModulate` and `phased.CFARDetector2D` all have hand written
replacements here. The code also runs unmodified on GNU Octave 8, which is how
it was verified.

## Quick start

```matlab
cd Bistatic-Passive-Radar
addpath('src')

% Confirm everything works.  Three to four minutes.
addpath('tests'); run_all_tests

% Regenerate every figure, table and CSV.  Ten to twenty minutes.
run scripts/run_all.m
```

Individual pieces:

```matlab
[wave, grid, info] = lte_generate(50, 1.0, 17, 20);   % 10 MHz, full load, 20 ms
[chi, tau, fd]     = caf(wave, wave, info.fs, info.samples_per_subframe, 600);
imagesc(fd, tau * 3e8, 20 * log10(abs(chi) / max(abs(chi(:)))));
```

Every function has a full help block with a worked example: `help caf`,
`help eca`, `help link_budget`.

## Results

### The ambiguity function and the cell load

Measured on 10 ms of signal, main lobe taken as two delay resolution cells
either side of the peak.

| Load `rho` | PSL (dB) | ISL (dB) | CRS ghost at 3.33 km (dB) |
|---|---|---|---|
| 0.00 | -2.6 | +5.0 | -2.6 |
| 0.25 | -20.0 | -4.8 | -20.0 |
| 0.50 | -21.0 | -6.8 | -31.1 |
| 0.75 | -20.6 | -7.6 | -40.5 |
| 1.00 | -20.7 | -7.9 | -45.7 |

(50 RB, 9 MHz. The other three bandwidths behave the same way to within a dB;
see `results/af_metrics.csv`.)

On an idle cell the integrated sidelobe level is **positive**: more energy sits
in the sidelobes than in the main lobe. A passive radar pointed at an idle cell
would report a ghost at 3.33 km, and another at 6.66 km, for every real target.
The traffic the cell carries is not a nuisance to be tolerated, it is the thing
that makes the waveform work as a radar signal.

### Where the false peaks come from

| Feature | Period | Domain | Predicted | Measured, idle | Measured, loaded |
|---|---|---|---|---|---|
| Cyclic prefix | Tu = 66.67 us | delay | 19.99 km | -22.6 dB | -23.2 dB |
| OFDM symbol period | 71.35 us | delay | 21.41 km | -54.8 dB | -48.6 dB |
| CRS comb, 6 subcarriers | 1/90 kHz | delay | 3.33 km | **-2.6 dB** | -45.7 dB |
| CRS comb, 2nd harmonic | | delay | 6.66 km | -6.2 dB | -49.2 dB |
| PSS and SSS | 5 ms | Doppler | 200 Hz | **-19.3 dB** | -64.3 dB |
| Radio frame | 10 ms | Doppler | 100 Hz | -63.4 dB | -67.4 dB |

**One correction to the PRD.** The PRD predicts the cyclic prefix ambiguity at
the OFDM symbol period, 71.35 us, which is 21.41 km. It is not there. The
cyclic prefix is a copy of the *tail of its own symbol*, and the two copies are
separated by the useful symbol duration Tu = 1/15 kHz = 66.67 us, not by
Tu + Tcp. The peak is at 19.99 km and the one at 21.41 km is 25 dB weaker. The
measurement is in `test_at2` and the report should quote 19.99 km.

### Cancellation

10 MHz channel, 20 ms, direct path 60 dB above the echoes, direct path 60 dB
above the noise, five clutter scatterers inside 3 km.

| Filter order K | Depth (dB) | Target loss (dB) |
|---|---|---|
| 0 | 19.5 | 1.5 |
| 64 | 24.9 | 1.5 |
| 128 | 28.8 | 2.0 |
| 160 | 53.8 | 0.4 |
| 224 | 53.8 | 0.4 |

Two things set the plateau, and both are visible in the sweep. K has to reach
past the furthest clutter scatterer, at 148 samples here, or the uncancelled
clutter sets the floor. Beyond that, the residual still contains the receiver
noise, so the depth can never exceed the direct to noise ratio, 60 dB.

**ECA against NLMS**, same filter order, same record:

| Canceller | Depth (dB) |
|---|---|
| NLMS, mu = 0.003 | 10.2 |
| NLMS, mu = 0.03 | 21.0 |
| NLMS, mu = 0.1 | 28.5 |
| ECA | **53.8** |

No step size gets NLMS within 25 dB of ECA over a 20 ms record. Small steps
have not converged by the end of the record; large steps converge fast to a
noisy solution. ECA has no such coupling because it solves for the weights in
closed form.

**The Doppler notch.** Cancellation fits its weights to data that contains the
target, so the fit absorbs any echo that looks stationary over a batch. The
notch is about `1/T_batch` wide, and the measurement confirms it. Target loss,
in dB, for a probe at 1 km bistatic range:

| Batch | 0 Hz | 10 Hz | 20 Hz | 40 Hz | 100 Hz | 200 Hz |
|---|---|---|---|---|---|---|
| 5 ms | 55.5 | 43.7 | 30.2 | 18.0 | 4.5 | 0.0 |
| 20 ms | 55.5 | 18.2 | 7.4 | 0.5 | 0.0 | 0.0 |

A target with zero Doppler is removed completely, whatever the batch length.
That is not a bug in the canceller, it is the definition of the problem: a
stationary target is indistinguishable from clutter.

One precondition that is easy to miss. ECA spans delays 0 to K samples and
nothing outside it, so a target beyond `K*c/fs` of bistatic range is untouched
whatever its Doppler. A target loss measurement made on a target outside the
span reports a comfortable zero that means nothing.

### Detection

Monte Carlo over the real chain: LTE waveform, synthesised echo, range-Doppler
map, CFAR decision. Pfa = 1e-4.

Post-processing SNR needed for Pd = 0.9, 100 trials per point, read off the
measured curve by linear interpolation:

| Configuration | 10 ms | 40 ms |
|---|---|---|
| 6 RB, 1.08 MHz | 13.4 dB | 13.3 dB |
| 25 RB, 4.50 MHz | 12.5 dB | 13.8 dB |
| 50 RB, 9.00 MHz | 14.4 dB | 14.2 dB |
| 100 RB, 18.00 MHz | 13.5 dB | 14.2 dB |

Against the 13 dB the link budget assumes. Every configuration lands within
1.5 dB of it, and the spread between them is consistent with the +-5% standard
error of a 100 trial estimate of Pd. This is the one number that ties M7 and M8
together, and the report should say that it was checked rather than assumed.

The measured false alarm rate on the radar maps stayed between 1.0e-4 and
1.1e-4 against a design value of 1e-4 throughout.

### Feasibility

60 dBm EIRP at 1800 MHz, 10 dBi receive antenna, 3 dB noise figure, 3 dB system
loss, 13 dB required after processing, free space.

| Target | RCS | Rmax at T = 0.05 s | Rmax at T = 0.2 s |
|---|---|---|---|
| Pedestrian | 0.1 m^2 | 6.8 km | 9.7 km |
| Small drone | 1 m^2 | 12.2 km | 17.2 km |
| Car | 10 m^2 | 21.7 km | 30.6 km |
| Truck | 100 m^2 | 38.5 km | 54.5 km |

**Bandwidth does not appear in this table, and that is a result rather than an
omission.** Widening the channel raises the noise power by B and raises the
coherent processing gain by B, and the two cancel exactly:

```
SNR after processing = (Pr / (k*T0*B*F)) * (B*T) = Pr*T / (k*T0*F)
```

All four bandwidths give the same maximum range. What the bandwidth buys is
range resolution, which improves from 138.8 m at 1.4 MHz to 8.3 m at 20 MHz, a
factor of 16.7. `results/feasibility.csv` carries all 32 cells; the resolution
column is printed alongside by `run_experiment5_feasibility.m`.

The quoted range is the symmetric case Rt = Rr = R. The radar equation
constrains the *product* Rt*Rr, so the real detection boundary is the Cassini
oval Rt*Rr = R^2. Near the baseline that oval bulges outwards, which looks like
extra coverage until the resolution figure is laid over it: the same region is
where cos(beta/2) collapses and range resolution becomes unbounded. About 1.7%
of the mapped plane has a resolution more than ten times worse than c/2B purely
because of where it sits relative to the baseline. Both are drawn on the same
axes in `figures/d6_geometry_coverage.pdf`.

## Two places where this implementation departs from the PRD

Both are deliberate, both are measured, and both should be stated in the report.

1. **The cyclic prefix delay ambiguity is at 19.99 km, not 21.41 km.** Reason
   above; measurement in `test_at2`.
2. **The maximum detection range does not depend on the channel bandwidth.**
   The PRD asks for a table across four bandwidths at two integration times, so
   the table has all 32 cells, but the bandwidth columns are identical by
   construction. `test_at8` proves the cancellation algebraically and the
   resolution column shows what the bandwidth does change.

A third, smaller one: 3GPP TS 36.211 staggers the second CRS symbol of each
slot by three subcarriers. The PRD specifies a single frequency shift
`mod(ncellid, 6)` for every CRS symbol, and that is what `lte_generate`
implements, which keeps the comb strictly periodic and makes the 3.33 km
prediction exact. The docstring says so.

## Limitations

These belong in the report as they stand. An honest limitations section is
worth more than an inflated results section.

1. **Simulation only.** No signal was captured and no hardware was used.
2. **The reference channel is assumed ideal.** `synth_rx` returns the
   transmitted waveform as the reference. A real reference channel contains
   multipath and would need reconstruction; that is explicitly out of scope,
   and every cancellation and detection number here is optimistic because of
   it.
3. **Two dimensional geometry.** Real targets have altitude. Every range here
   is a ground range.
4. **A single illuminator.** One bistatic ellipse does not fix a position. A
   second baseline or an angle measurement would be needed, and neither is
   modelled.
5. **No range migration compensation.** A target moving at 100 m/s crosses a
   33 m range cell in 0.33 s, so at the 0.2 s integration time of the link
   budget a fast target is already smearing across cells. The detection
   experiments use 10 and 40 ms, where this does not bite; the feasibility
   table uses 0.2 s, where it would.
6. **Free space propagation.** No terrain, no buildings, no atmospheric or rain
   loss. Every range in the feasibility table is an upper bound, and a real
   deployment over a city will fall well short of it.
7. **Non-fluctuating targets and a fixed bistatic RCS.** No Swerling model, and
   no dependence of RCS on the bistatic angle, which for a real target can be
   tens of dB.

## Notes on running this

- **Figures.** `figures/` is populated by running the scripts in MATLAB. The
  scripts were verified headless, so the numbers and CSVs in `results/` are
  real, but the PDFs have to be generated once on a machine with a display.
  `figures/README.md` lists which script writes which file.
- **MATLAB Online free tier.** 20 hours a month, 15 minute idle timeout. The
  full `run_all.m` takes ten to twenty minutes, most of it the Monte Carlo in
  experiment 4; set `QUICK = true` before running it while developing.
  `wave_cache` reloads the waveform library from `data/` instead of
  regenerating it, which is the main saving.
- **Repeatability.** Every script and test calls `set_seed` before generating
  anything random, so two runs give identical numbers. Change a seed and the
  PAPR figures will move by a few tenths of a dB; PAPR is a random variable and
  its maximum grows slowly with record length.
- **Headless runs.** Set `MAKE_FIGURES = false` in the base workspace before
  running any experiment script to compute and write the CSVs without plotting.

## Where to look first

If you are picking this up cold, read in this order: `src/lte_generate.m` for
what the signal is, `src/caf.m` for what is done to it, then
`tests/test_at2.m`, which is where the physics of the LTE ambiguity function is
actually pinned down against measurement.
